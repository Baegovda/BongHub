# BongHub.Next

## 0.4.0

메모리와 설정 첫 프레임. 화면과 저장 형식은 0.3.0과 같아요.

- `ConcurrentGarbageCollection`을 켰어요. 0.3.0 기준선에서 끄면 설정 첫 프레임 중앙값이 1648ms(한 번은 3795ms)였고, 켜면 684ms였어요. 트레이는 56MB, 아이콘까지 293ms예요.
- 창을 띄울 때 불투명도 애니메이션이 끝난 뒤 시계를 떼요. 시계가 남아 있으면 창 크기만큼의 중간 표면이 유휴 동안 남아요. 설정 창의 빛 번짐도 같은 색을 브러시에 넣어서, 타원 전체에 `Opacity`를 걸지 않아요.
- 스티커 메모의 `\jpegblip` / `\pngblip`은 화면 크기(긴 변 1280px 이하, 시스템 DPI와 확대 반영)로만 디코딩해요. 저장할 때는 그 비트맵을 다시 그리지 않고, 파일에 있던 pict 묶음을 그대로 끼워 넣어요. 3.4.x가 읽는 그림 바이트는 유지돼요. WPF가 pict 개수를 맞추지 못하면 예전처럼 기존 `.rtf`를 두고 본문만 메타에 적어요.
- 시작 메모를 다 연 뒤(열 메모가 없으면 첫 프레임을 기록한 뒤) 큰 객체 힙을 한 번 압축해요. 20초 유휴를 재기 전에 버린 비트맵이 작업 집합에 남지 않게 하려는 거예요.
- 노트 테스트에 표시 비트맵 크기와 저장 후 pict 바이트 길이 확인을 더했어요. 스모크는 56, 노트는 25예요.

## 0.3.0

0단계 기준선. 매일 쓰는 기능은 0.2.0 메모·설정 프로토타입과 같아요.

- 대상 프레임워크를 `net10.0-windows`로 올렸어요. SDK 기준은 10.0.403이고, 같은 10 기능 대역의 더 높은 SDK로 진행할 수 있어요.
- 트레이를 H.NotifyIcon.Wpf 2.4.1로 바꿨어요. `UseWindowsForms`는 뺐어요. 왼쪽 클릭은 설정을 열고, 오른쪽 클릭은 다크 메뉴, 종료만 프로세스를 끝내요.
- 게시는 ReadyToRun, `win-x64`, 프레임워크 종속이에요. 단일 파일, 트림, Native AOT는 꺼 두었어요.
- 메모리 기준선은 `next/measure-baseline.ps1`예요. 트레이만, 설정 창, 설정 창을 숨긴 뒤, 메모 7개를 각 3회 재고, `ConcurrentGarbageCollection`을 켠 경우와 끈 경우를 같이 남겨요. 기본값은 여전히 꺼짐이에요.
- `next_startup.txt`에 트레이 아이콘이 보인 시각과 첫 `ContentRendered`를 같이 적어요.
- `%LOCALAPPDATA%\BongHub`의 형식과 `Local\BongHub_NotesWriter` 잠금 순서는 그대로예요. `Local\BongHub_Tray`는 만들지 않아요.
