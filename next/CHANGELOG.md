# BongHub.Next

## 0.5.0

1단계. 스티커 메모를 트레이 3.4.9와 같은 매일 쓰는 동작으로 맞춰요. 저장 형식과 잠금, 소프트웨어 렌더는 0.4.0 그대로예요.

- 새 메모 단축키는 `Notes.Hotkey`(기본 Ctrl+Alt+N)를 `RegisterHotKey` id 900, `MOD_NOREPEAT`로 등록해요. 설정에서 바꾸는 즉시 다시 등록하고, 실패하면 풍선을 띄워요. 비우면 등록하지 않아요. `--off`와 스모크·노트 테스트는 등록하지 않아요. 테스트는 `WM_HOTKEY`와 같은 처리만 호출해요. `SetWindowsHookEx`는 쓰지 않아요.
- 삭제(빈 메모는 바로, 내용이 있으면 확인), 모두 보이기, 모두 숨기기, 모든 메모 텍스트 복사, 선택 메모 색. 트레이 메뉴에도 모두 보이기·숨기기가 있어요.
- 글자 크기는 7–48pt예요. 메모 안에서는 텍스트 11, 제목1 24, 제목2 20, 제목3 16, 제목4 13과 Ctrl++/− 가 있어요. 색 팔레트는 호버로 미리 보고, 클릭해야 저장해요. 맞춤 색은 `c:RRGGBB:RRGGBB`예요.
- 링크 클릭, 이미지 파일 드롭·붙여넣기·파일 선택. 새 그림은 `\pngblip` 또는 `\jpegblip`이고, 이미 1600px 이하인 PNG/JPEG 파일 바이트는 다시 인코딩하지 않아요. 크기 변경은 `\picwgoal`/`\pichgoal`만 바꿔요. 25/50/75/100, 폭 맞춤, 이동, 복사, 더블클릭 뷰어가 있어요.
- 메모 RTF는 WPF `RichTextBox`의 `TextRange`로 읽고 써요. msftedit는 쓰지 않아요.
- 표시 직후 `WS_EX_NOACTIVATE`를 풀어요. 모달 중에는 메모 창을 다시 활성화해요. 화면 밖은 작업 영역으로 클램프해요. `--off`에서는 클램프하지 않고, WPF가 창을 실제 모니터로 끌어오면 `WM_WINDOWPOSCHANGING`에서 마지막 화면 밖 좌표로 되돌려요. 전역 후킹은 아니에요.
- 고치지 않은 메모는 파일 바이트를 그대로 둬요. 고친 메모를 저장할 때 화면에 있는 그림이 RTF에서 빠지면 파일을 덮어쓰지 않고 `next_error.log`에 남겨요. 창 없는 재현은 Windows CI가 STA에서 1×1 `\pngblip`을 `TextRange`로 읽고 쓰는 거예요.
- 8MB를 넘으면 메모 안에 경고를 보여요. 대화상자로 테스트를 막지 않아요.
- 스모크 **65**, 노트 **89**(`data/notes` 7개에 그림이 있을 때). 0.4.0의 58과 26은 그 안에 들어 있어요.

## 0.4.0

메모리와 설정 첫 프레임. 화면과 저장 형식은 0.3.0과 같아요.

- `ConcurrentGarbageCollection`을 켰어요. 0.3.0 기준선에서 끄면 설정 첫 프레임 중앙값이 1648ms(한 번은 3795ms)였고, 켜면 684ms였어요. 트레이는 56MB, 아이콘까지 293ms예요.
- 창을 띄울 때 불투명도 애니메이션이 끝난 뒤 시계를 떼요. 시계가 남아 있으면 창 크기만큼의 중간 표면이 유휴 동안 남아요. 설정 창의 빛 번짐도 같은 색을 브러시에 넣어서, 타원 전체에 `Opacity`를 걸지 않아요.
- 스티커 메모의 `\jpegblip` / `\pngblip`은 화면 크기(긴 변 1280px 이하, 시스템 DPI와 확대 반영)로만 디코딩해요. 저장할 때는 그 비트맵을 다시 그리지 않고, 파일에 있던 pict 묶음을 그대로 끼워 넣어요. 3.4.x가 읽는 그림 바이트는 유지돼요. WPF가 pict 개수를 맞추지 못하면 예전처럼 기존 `.rtf`를 두고 본문만 메타에 적어요.
- 시작 메모를 다 연 뒤(열 메모가 없으면 첫 프레임을 기록한 뒤) 큰 객체 힙을 한 번 압축하고, 600ms 더 기다렸다가 더 이상 안 쓰는 페이지만 작업 집합에서 내려요. 이 정리는 private 바이트를 줄이지 않아요. 첫 프레임을 적은 뒤에만 돌아서 `first_frame_ms`에는 안 들어가요.
- 프로세스를 소프트웨어 렌더로 고정했어요. `38e6b9b`를 주인 PC에서 재었을 때(동시 GC, 3회 중앙값) 트레이는 60MB·아이콘 약 290ms, 설정 첫 프레임 662ms로 목표 안이었지만, 설정 창은 작업 집합 195MB(private 162MB), 메모 7개는 240MB(private 212MB)였어요. 관리 힙은 5–6MB라 창 내용이 아니라 첫 하드웨어 창이 올리는 D3D9On12 장치예요. 소프트웨어 래스터는 그 장치를 만들지 않아요.
- 소프트웨어 래스터는 클라이언트 알파를 DWM에 넘기지 못해요. 반투명 틴트를 그대로 두면 검정에 곱해져 설계색보다 어두워지므로, Mica가 없을 때와 같은 불투명 색으로 그려요. Mica 속성은 여전히 요청해요. 그라데이션, 글꼴, 메모 색, 둥근 모서리, 열기 애니메이션은 유지해요. 바탕화면이 틴트 뒤로 비치는 모습은 이 경로에서는 보이지 않아요.
- 열기·페이지 전환의 불투명도·확대 시계는 끝나면 떼고 변환도 원래대로 돌려요. 시계가 남아 있으면 창 크기 중간 표면이 유휴 동안 남아요.
- 메모 그림 확대는 Linear예요. HighQuality는 화면 크기 비트맵을 한 장 더 캐시하고, 소프트웨어 래스터에서는 느리기도 해요. 저장할 때 파일에 있던 pict 묶음을 끼워 넣는 동작은 그대로예요.
- 스모크 58(설정 창·메모 창이 소프트웨어 렌더인지 2개), 노트 26(그림 확대가 Linear인지 1개). 그림 바이트 길이 확인은 그대로예요.
- `fb8d5f2`를 Windows에서 재었을 때 메모리는 목표 아래(트레이 작업 집합/private 8/18MB, 설정 23/65, 메모 7개 22/95, 아이콘 294ms)였고, 설정 첫 프레임만 중앙값 706ms(652, 706, 2386)로 700ms를 넘었어요. GPU일 때는 651–678ms였어요. 소프트웨어에서 `main_ctor_done`→`main_hwnd`가 190–250ms예요.
- 그 첫 페인트를 줄이려고, 설정 창을 처음 띄울 때는 루트 불투명도 애니메이션을 하지 않아요. 소프트웨어에서는 그 애니메이션이 창 전체를 중간 표면에 한 번 더 그립니다. 다시 열 때는 예전처럼 페이드해요. 메모 창 페이드는 그대로예요.
- 빛 번짐 타원(방사 그라데이션)은 첫 프레임을 기록한 뒤에 보여요. 첫 소프트웨어 래스터에서 빼기 위해서예요. 단축키 캡은 UiFont를 그대로 써요. `FontFamily`를 새로 만들면 첫 프레임에서 글꼴 목록을 뒤집니다. 소프트웨어일 때는 Mica DWM 호출을 하지 않아요. 불투명하게 그리므로 화면에 차이가 없고, 호출이 첫 프레임 경로에 있었어요.
- Windows에서 확인한 유휴(작업 집합/private): 트레이 8/18MB, 설정 20/64MB, 메모 7개 22/94MB. 설정 첫 프레임 593ms. 스모크 58, 노트 26.
- Notes 설정 한 키를 저장할 때 `config.json`에서 그 값만 바꾸고, 나머지 바이트는 그대로 둬요. 값이 같으면 파일을 다시 쓰지 않아요. 0.4.0의 메모리 변경과 같이 적용돼요.

## 0.3.0

0단계 기준선. 매일 쓰는 기능은 0.2.0 메모·설정 프로토타입과 같아요.

- 대상 프레임워크를 `net10.0-windows`로 올렸어요. SDK 기준은 10.0.403이고, 같은 10 기능 대역의 더 높은 SDK로 진행할 수 있어요.
- 트레이를 H.NotifyIcon.Wpf 2.4.1로 바꿨어요. `UseWindowsForms`는 뺐어요. 왼쪽 클릭은 설정을 열고, 오른쪽 클릭은 다크 메뉴, 종료만 프로세스를 끝내요.
- 게시는 ReadyToRun, `win-x64`, 프레임워크 종속이에요. 단일 파일, 트림, Native AOT는 꺼 두었어요.
- 메모리 기준선은 `next/measure-baseline.ps1`예요. 트레이만, 설정 창, 설정 창을 숨긴 뒤, 메모 7개를 각 3회 재고, `ConcurrentGarbageCollection`을 켠 경우와 끈 경우를 같이 남겨요. 기본값은 여전히 꺼짐이에요.
- `next_startup.txt`에 트레이 아이콘이 보인 시각과 첫 `ContentRendered`를 같이 적어요.
- `%LOCALAPPDATA%\BongHub`의 형식과 `Local\BongHub_NotesWriter` 잠금 순서는 그대로예요. `Local\BongHub_Tray`는 만들지 않아요.
- Notes 설정 한 키를 저장할 때 `config.json`에서 그 값만 바꾸고, 나머지 바이트는 그대로 둬요. 값이 같으면 파일을 다시 쓰지 않아요.
